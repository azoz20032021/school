# نظام إدارة ثانوية المعالي الأهلية

نظام إدارة شؤون الطلاب: الحسابات، التسجيل والموافقات، الدرجات، الحضور، السلوك،
الأقساط والرسوم المالية، والتقارير.

---

## التشغيل محلياً

```bash
npm install
cp .env.example .env.local     # ثم عبّئ القيم
npm run dev                    # http://localhost:3000
```

## أوامر أخرى

| الأمر | الوظيفة |
|---|---|
| `npm run dev` | خادم التطوير (Vite + API معاً) |
| `npm run build` | بناء الواجهة للإنتاج |
| `npm run lint` | فحص الأنواع (TypeScript) |
| `npm start` | تشغيل الإنتاج من مجلد `dist` |

---

## بنية المشروع

```
backend/            كل منطق الـ API (مشترك بين كل بيئات التشغيل)
  app.ts            تجميع تطبيق Express
  lib/              قاعدة البيانات، المصادقة، التحقق، السجل، الكاش
  routes/           نقاط النهاية موزعة حسب المجال
api/index.ts        غلاف Vercel فقط (لا يحتوي منطقاً)
server.ts           تشغيل على Node عادي (VPS / Azure / Railway ...)
src/                واجهة React
firestore.rules     قواعد أمان قاعدة البيانات
```

> **لماذا `backend/` منفصل عن `api/`؟**
> على Vercel كل ملف `.ts` داخل `api/` يتحول إلى دالة serverless مستقلة.
> إبقاء الكود المشترك خارجه يمنع إنشاء دوال عبثية، ويجعل المشروع قابلاً للنشر
> على أي استضافة أخرى بدون تعديل.

## الإعداد لأول مرة

### 1. مفتاح الجلسات (إلزامي)

```bash
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
```

ضع الناتج في `SESSION_SECRET`. **بدونه يستطيع أي شخص تزوير جلسة مدير.**

### 2. إقفال قاعدة البيانات (إلزامي)

بدون هذي الخطوة، أي شخص يفتح console بالمتصفح يقدر يقرأ قاعدة البيانات كاملة.
الخطوات في [`DEPLOYMENT.md`](DEPLOYMENT.md#إقفال-قاعدة-البيانات).

### 3. إنشاء أول حساب مدير

يعمل هذا الطلب **فقط** إذا لم يكن هناك أي مدير في النظام:

```bash
curl -X POST https://YOUR-DOMAIN/api/setup \
  -H "Content-Type: application/json" \
  -d '{"name":"مدير النظام","uid":"ADM001","password":"كلمة-مرور-قوية"}'
```

## نظام التسجيل الجديد

1. الطالب يفتح `/register` ويعبّئ بياناته الكاملة على 4 خطوات ويختار كلمة مروره.
2. يستلم **رقم متابعة** ويقدر يتابع حالة طلبه من `/register/status`.
3. الإدارة تراجع الطلب من صفحة **الطلبات**، وتوافق أو ترفض مع بيان السبب.
4. عند الموافقة: يُنشأ الحساب، ويتولد رقم تعريفي (UID) تلقائياً بصيغة `YYNNNN`،
   ويُسجّل الطالب في الصف، ويصله إشعار — مع إمكانية إصدار القسط الأول مباشرة.

الحساب لا يستطيع الدخول قبل الموافقة.

## النظام المالي

- **سندات الرسوم**: تُصدر لطالب واحد أو صف كامل أو جميع الطلاب دفعة واحدة.
- **الدفعات**: كل دفعة لها رقم وصل، وتُحدّث حالة السند تلقائياً
  (`غير مسدد` / `مسدد جزئياً` / `مسدد`).
- **حالة كل طالب**: صفحة المالية تعرض لكل طالب إجمالي المستحق والمسدد والمتبقي،
  مع فلترة "المتبقي عليهم فقط" وهاتف ولي الأمر للتواصل.
- الطالب يشوف حسابه المالي في صفحة **المالية**.
- العملة: الدينار العراقي (IQD).

تسجيل الدفعات يتم داخل transaction، فلا تختل الأرصدة لو سجّل موظفان دفعة في نفس اللحظة.
